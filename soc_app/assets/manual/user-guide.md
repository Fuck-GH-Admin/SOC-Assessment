# 完整用户指南

## 1. 应用界面

应用名称为“碳盾 · SOC-Shield”，主要页面分为四栏。桌面宽屏（≥900px）使用左侧导航栏（可展开/收起），移动端使用底部导航栏，两端的页面结构一致：

| 页面 | 主要用途 |
|---|---|
| 计算 | 输入评估条件、计算当前土层、查看结果（桌面端为参数/结果双栏布局） |
| 图表 | 按“概览 / 剖面与侵蚀 / 管理情景 / 高级分析”四个分区查看叙事化图表 |
| 恢复力 | 分层恢复力证据、侵蚀亏缺矩阵、秸秆情景覆盖对照（第五章 5.1 口径） |
| 报告 | 本地确定性评估摘要（默认、离线）与可选 AI 辅助解读 |

评估条件、辅助观测、管理情景在“计算”页分组呈现：辅助观测（pH、含水量、黏粉粒、全氮）与管理情景（秸秆碳输入核算）默认折叠并标注“可选”，它们不改变核心计算结果。

历史记录、PDF 导出入口位于应用栏右上角；设置同样从应用栏进入。页面切换不会自动删除已填写的参数。应用关闭或被系统终止时，可通过草稿恢复最近一次未完成输入。

### 1.1 评估状态

计算页顶部有状态条，指示当前评估所处阶段：

| 状态 | 含义 |
|---|---|
| 未计算 | 尚未执行计算 |
| 计算完成未保存 | 已生成结果，可以导出 PDF 与查看图表 |
| 参数已修改 | 修改任意参数后旧结果立即失效，需重新计算 |

导出 PDF、图表分析仅在结果有效时可用，避免参数与结果、报告错配。

## 2. 首页“计算”页

### 2.1 施肥方式

可选“施肥”和“未施肥”。两者对应原始数据中的 `F` 和 `UNF` 两套独立数据。应用不会在查表结果上再次叠加施肥系数。

### 2.2 侵蚀程度

可选 `0/10/20/30/40/50/60/70cm`。这里的数值表示原始数据中的侵蚀处理等级。`0cm` 是 CK 比较使用的参考处理，不表示没有土层厚度。

### 2.3 土层范围

可选范围及其数据键如下：

| 页面显示 | 数据键 | 厚度 |
|---|---:|---:|
| 0-20cm（表层） | 10 | 20cm |
| 20-30cm（亚表层） | 25 | 10cm |
| 30-40cm（中层） | 35 | 10cm |
| 40-50cm（深层） | 45 | 10cm |
| 50-60cm（底层） | 55 | 10cm |

页面使用实际范围名称，数据键只用于内部查表和科学附录解释。

### 2.4 统一土壤容重

单位为 `g/cm³`，允许范围为 `0.5-2.5`。应用用一个统一容重输入换算当前土层和 0-60cm 剖面，因此这是简化假设。若不同土层容重差异很大，应在专业分析中单独说明。

### 2.5 辅助观测参数

| 参数 | 允许范围 | 当前用途 |
|---|---:|---|
| pH | 3-11 | 辅助观测和报告解释 |
| 含水量 | 0-100% | 辅助观测和报告解释 |
| 黏粉粒含量 | 0-100% | 辅助观测和报告解释 |
| 全氮含量 | 0-10g/kg | 辅助观测和报告解释 |

这些参数不会改变 SOC 查表值、碳库公式或 CK 比较结果。

### 2.6 秸秆与凋落物参数

| 参数 | 单位/范围 | 当前用途 |
|---|---|---|
| 秸秆生物量 | `kg/ha`，不能为负 | 秸秆碳输入 |
| 秸秆碳含量比例 | `0-1` | 秸秆碳输入 |
| 基础凋落物碳输入 | `kg C/m²`，不能为负 | 系统总碳输入 |

这三项只进入 30%、50%、100% 秸秆还田情景，不会反向修改实测 SOC。

### 2.7 输入校验

点击计算后，应用检查：

- 数值是否为有限数值。
- 施肥方式、侵蚀等级和土层键是否在支持范围内。
- 容重、pH、含水量、黏粉粒、全氮和情景参数是否在允许范围内。
- 用于剖面评估的土层是否能够连续覆盖 0-60cm。

输入错误会显示在结果上方。修正参数后再次点击计算即可。

### 2.8 恢复默认参数

点击“恢复默认参数”会恢复默认输入、清空当前结果并删除草稿。已保存的历史记录不会被删除。

## 3. 计算结果

### 3.1 SOC 含量

SOC 由“施肥方式 × 侵蚀程度 × 土层”直接查表得到，单位为 `g/kg`。它不是由 pH、含水量、黏粉粒或全氮回归计算得到。

### 3.2 当前土层碳储量

应用使用当前土层的真实厚度和统一容重计算碳库，单位为 `kg C/m²`。0-20cm 土层使用 20cm 厚度，其余页面土层使用 10cm 厚度。

### 3.3 碳密度

碳密度是碳库除以土层厚度（米），单位为 `kg C/m³`。它用于在不同厚度土层之间比较，不应与碳库储量混为一谈。

### 3.4 当前土层相对 CK 碳库差

应用查找同一施肥方式、同一土层、侵蚀 0cm 的 CK 碳库，并计算：

```text
当前土层碳库 - 同层 CK 碳库
```

正值表示当前处理高于 CK，负值表示低于 CK，接近零表示两者接近。

### 3.5 折算代理

当前土层差值除以 20 的结果以 `kg C/m²/yr` 显示。它只是把静态差异按固定年数折算后的参考值，不是逐年测量结果。

### 3.6 SOC 损失率

应用按同层 CK 的 SOC 作为分母计算损失率。当前 SOC 高于 CK 时，损失率按 0 处理；CK 为零时不计算有效损失率。

### 3.7 结果失效

修改任意参数会清空旧结果，并重置 AI 状态。这样可以避免参数、计算结果、图表、AI 报告和 PDF 混用。重新计算后才会建立新的结果和历史记录。

## 4. 0-60cm 剖面评估

### 4.1 剖面范围

应用会根据当前施肥和侵蚀处理构建 0-20、20-30、30-40、40-50、50-60cm 五个土层，并用侵蚀 0cm 构建同划分的 CK 剖面。

### 4.2 剖面校验

剖面必须：

- 从 0cm 开始。
- 连续覆盖到 60cm。
- 没有重叠或缺口。
- 在 20cm 处有明确边界。
- 当前剖面和 CK 剖面使用相同土层划分。

校验失败时，单层计算仍可能成功，但应用会显示剖面 CK 评估失败的提示。

### 4.3 剖面结果

- `0-20cm 碳库`：当前剖面表层的碳库。
- `0-60cm 碳库`：五个土层碳库之和。
- `0-60cm 相对 CK 差`：当前完整剖面与 CK 完整剖面的静态差异。
- `0-20cm 相对 CK 差`：当前表层与 CK 表层的静态差异。
- `0-60cm 差值/20 年`：完整剖面静态差异的折算代理。

### 4.4 状态文字

状态文字表示当前完整剖面相对同施肥 CK 是“高于”“低于”还是“接近”。它是当前数据的比较结论，不是恢复速度等级或未来预测。

## 5. 秸秆还田情景

应用固定生成三种情景：30%、50% 和 100% 秸秆还田。每种情景显示秸秆碳输入和系统总碳输入。

情景用于比较管理输入潜力，不会修改已查到的 SOC 或碳库，也不等同于土壤有机碳实际增加量。

## 6. 图表

图表按四个分区组织，每张图表先回答一个明确问题，并给出由当次计算数据推导的一句话结论（含关键数字），图表仅作为该结论的可视化证据：

| 分区 | 内容 |
|---|---|
| 概览 | 评估雷达（归一化展示）、剖面碳库组成 |
| 剖面与侵蚀 | SOC 垂直分布、当前 vs CK 分层对照、侵蚀梯度 |
| 管理情景 | 秸秆还田碳输入核算 |
| 高级分析 | 侵蚀×土层热力矩阵、侵蚀-SOC 分布 |

结论文字由应用按查表数据自动生成，例如“当前 10cm 处表层 SOC 较 CK 降低 26%”，或提示数据中的非单调回升点。结论与图表都来自同一份计算结果，不存在独立的“图表数据”。

### 6.1 侵蚀图

展示当前施肥方式下，八个侵蚀等级对应的 0-20cm SOC。纵轴为 `SOC (g/kg)`，横轴为侵蚀程度 `cm`。

### 6.2 深度图

展示当前施肥和侵蚀组合下五个土层的 SOC 垂直分布。它使用不同土层的查表值，不是将当前单层结果外推到全部剖面。

### 6.3 秸秆图

展示三种还田比例的系统总碳输入，并将基础凋落物与秸秆碳输入分段显示。单位为 `kg C/m²`。

### 6.4 评估雷达图

将 SOC、碳库储量、碳密度、相对 CK 损失和相对 CK 差按固定展示区间归一化到同一尺度。它是同屏观察工具，不是统计学综合评分。

### 6.5 组成图

展示 0-60cm 五个土层对剖面碳库的贡献比例。比例基于分层碳库，不是 SOC 浓度占比。

### 6.6 关联图

展示八个侵蚀等级与 0-20cm SOC 的数据分布。图中不拟合因果模型，不能据此推断因果关系。

### 6.7 对比图

将当前侵蚀处理与同施肥 CK 的五层 SOC 分布放在一起比较。

### 6.8 热力图

按侵蚀程度和土层显示 SOC 矩阵，单元格单位为 `g/kg`。颜色表示数值高低，不能替代具体数值读取。

## 7. 报告

报告页提供两层内容：

1. **评估摘要（默认）**：由应用根据当前计算结果直接生成的一句话结论与关键指标表。本地生成、离线可用、不经过任何模型。
2. **辅助解读（可选）**：将当前参数与结果发送到用户配置的 AI 服务，生成解读文字。生成内容仅供参考，不参与任何计算。使用前需在设置中配置服务商与 API Key。

### 7.1 支持的服务商

设置页提供以下预设：

| 服务商 | 默认地址 | 默认模型 | API Key |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-v4-flash` | 必填 |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1` | 必填 |
| Groq | `https://api.groq.com/openai/v1` | `openai/gpt-oss-120b` | 必填 |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-v4-flash` | 必填 |
| 自定义 | 用户填写 | 用户填写 | 可选 |

所有服务都按 OpenAI 兼容的 `/chat/completions` 接口请求。地址可以填写基础地址，也可以直接填写完整接口地址；应用会避免重复拼接。

### 7.2 配置步骤

1. 进入“设置”。
2. 选择服务商，或选择“自定义”。
3. 填写 API 基础地址或完整接口地址。
4. 填写 API Key 和模型名称。
5. DeepSeek 等支持思考模式的服务可以打开思考模式并选择推理强度。
6. 点击“保存”。

API Key 保存在系统安全存储中。不要把真实 Key 写入 JSON、说明书、截图、日志或提交记录。

### 7.3 生成、取消和重新生成

完成计算后进入“图表”页，点击“生成报告”。报告正文会流式显示；思考模式下，服务返回的思考内容会单独显示。生成过程中可以点击“取消”，完成后可以点击“重新生成”。

参数变化会使当前 AI 报告失效。新报告只会绑定最近一次计算的参数、结果和剖面结果。

### 7.4 错误处理

- 未配置 Key：先进入设置配置。
- 网络连接失败：检查网络、代理和接口地址。
- HTTP 错误：检查 Key、模型和服务商权限。
- 空闲超时：报告可能只有部分内容，应重新生成。
- 自定义服务：若服务商不要求 Key，可以留空，但仍需提供有效接口地址和模型。

AI 文本是辅助解释，不替代原始数据、统计分析或土壤学专业判断。

## 8. PDF 报告

### 8.1 报告内容

PDF 通常包含：

- 生成时间和算法版本。
- 输入参数表。
- 当前土层计算结果。
- 20 年/100 年字段的静态口径说明。
- CK 参考剖面差和秸秆情景。
- 数据图表。
- 当前计算匹配的 AI 报告（如果已生成）。

### 8.2 应用本地副本

PDF 写入应用文档目录下的 `SOC-Shield/report_pdfs/`，文件名为 `soc-report-<记录ID>.pdf`。同一历史记录再次导出时覆盖自己的副本，不产生重复孤立文件。

### 8.3 Windows

Windows 可以打开 PDF、打开所在文件夹、复制路径，并可将 PDF 另存到应用目录之外。外部另存副本不由历史记录管理。

### 8.4 Android

Android 使用系统分享面板分享应用本地 PDF。分享不会删除或替换应用本地副本。

### 8.5 文件缺失

如果用户在系统文件管理器中删除了应用 PDF，历史页再次访问时会清理失效关联。删除历史记录时，应用会尝试同时删除受控目录中的关联 PDF。

## 9. 历史记录

### 9.1 自动保存

每次成功计算会写入一条历史记录。连续点击同一组未变化的参数不会重复写入相同记录。

记录包括参数、计算结果、剖面结果、创建时间、标签、算法版本和可选 PDF 路径。

### 9.2 查看详情

点击记录可以查看完整参数、SOC、碳库、碳密度、CK 差异、损失率、剖面结果、算法版本和 PDF 状态。

### 9.3 重命名

在详情中选择“重命名”。名称最多 80 个字符；留空会恢复默认的“`SOC 计算 #编号`”名称。

### 9.4 载入参数

载入只恢复输入参数，不直接恢复旧结果。载入后重新计算会使用当前算法版本。若记录来自旧算法，应用会先提示结果可能不同。

### 9.5 删除

删除历史记录前会二次确认。删除记录会同时尝试删除应用管理目录中的 PDF；用户另存到外部目录的副本不受影响。

## 10. 草稿

### 10.1 自动保存规则

输入停止约 2 秒后保存一条固定 ID 的草稿。草稿包含计算参数，不包含历史记录、AI 报告或 PDF。

### 10.2 恢复规则

下次启动时，如果草稿未超过 7 天，应用会询问是否恢复。选择“恢复”会覆盖当前首页输入；选择“忽略”会保留草稿，直到恢复、成功计算、手动重置或过期清理。

### 10.3 过期规则

超过 7 天的草稿会在启动检查时自动删除，不再提示恢复。

## 11. JSON 导入导出

### 11.1 导出内容

导出文件包含版本号、导出时间和每条记录的参数、结果、剖面结果、标签、创建时间和算法版本。

### 11.2 不导出的内容

- 应用本地绝对 PDF 路径。
- PDF 二进制内容。
- API Key 和其他敏感配置。

### 11.3 导入限制

- 只接受 JSON 文件。
- 文件大小上限为 20MB。
- 记录数上限为 10000 条。
- 文件版本必须在当前支持范围内。
- 每条记录的参数、结果和时间字段必须符合格式。

导入在数据库事务中执行。导入失败时不会只写入一部分记录。

### 11.4 导入后的版本

导入会保留记录原始创建时间和算法版本。导入旧算法记录后，查看时仍可追溯；重新载入参数计算时使用当前算法。

## 12. 多记录对比

### 12.1 选择记录

在历史页点击对比图标进入对比页。最多选择 5 条记录，选择顺序会显示在记录标记中。

### 12.2 参数和结果表

表格会横向展示算法版本、施肥、侵蚀、土层、容重、辅助参数、秸秆情景参数、SOC、碳库、碳密度、CK 差异、折算代理和损失率。若记录有剖面结果，还会显示剖面和情景对比。

### 12.3 雷达图限制

当前雷达图只绘制选择顺序中的前两条记录；选择 3-5 条时，完整信息以表格为准。不同算法版本的记录会显示警告并隐藏雷达图，避免混合口径比较。

## 13. 设置中的其他选项

### 13.1 主题

可以选择配色方案和跟随系统、浅色、深色三种外观模式。主题只影响界面显示，不改变计算结果。

### 13.2 关于

关于区域显示应用名称和版本号，并提供问题反馈/源码链接。

## 14. 平台差异

| 功能 | Windows | Android |
|---|---|---|
| PDF | 打开、定位文件夹、复制路径、另存 | 系统分享、复制路径 |
| API Key | Windows 安全存储 | Android Keystore 安全存储 |
| 数据库 | 应用文档目录 SQLite | 应用文档目录 SQLite |
| 网络 | 使用系统网络和代理配置 | 使用设备网络；发布版需要网络权限 |

## 15. 数据与隐私

历史、草稿和应用 PDF 保存在本机应用私有目录。AI 报告生成时，当前计算参数和结果会发送到用户配置的外部 AI 服务商。使用第三方服务前，应确认其隐私政策和数据处理范围。

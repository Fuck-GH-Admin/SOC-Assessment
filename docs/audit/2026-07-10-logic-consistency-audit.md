# 2026-07-10 业务逻辑一致性审计

## 审计结论

此前的静态分析、单元测试和 Release 构建均已通过，但这些结果只能证明“现有实现按现有测试运行”，不能证明业务口径本身正确。

本轮重新以原始 HTML 数据表和第五章 DOCX 方法说明为依据，对计算、静态 CK 差异指标、图表、AI、历史记录和草稿生命周期进行交叉检查。发现的主要问题如下。

## P0：会造成指标含义错误或误导

- [x] `baseData` 已按施肥处理分别存储，计算时又对 `UNF` 乘 `0.92`，存在施肥影响二次修正。
- [x] 当前土层“净变化量”实际是 `SOC × 经验系数`，并不是当前碳库减同层 CK 碳库。
- [x] 深层损失率仍使用 0–20cm 表层 CK 作分母，跨土层比较不成立。
- [x] 应用没有逐年模拟数据，却把 CK 空间差异直接标为“20年/100年恢复趋势”。
- [x] 时间趋势图使用硬编码示意数组，却以真实趋势图形式展示。
- [x] 首页土层下拉框仍显示“10cm/25cm”，与计算引擎当前采用的“0–20/20–30...”土层语义不一致。

## P1：状态或数据生命周期不协调

- [x] 连续点击“计算”可能重复写入多条相同历史记录。
- [x] 历史记录没有算法版本，算法升级前后的结果会被当作同一口径比较。
- [x] AI 报告旧请求取消后仍可能回写，覆盖新请求或参数变化后的状态。
- [x] 草稿仅保留 5 分钟；恢复默认值还会重新保存一份默认草稿。
- [x] pH、含水量、黏粉粒、全氮不进入当前核心计算，但界面没有说明。
- [x] 秸秆碳含量和基础凋落物输入参与情景公式，却不能在界面修改。
- [x] 计算写库期间修改参数会让旧异步结果覆盖新参数，或留下意外历史记录。
- [x] 历史列表缓存未在新计算成功后失效，返回历史页可能看不到最新记录。

## P2：可用性与解释性不足

- [x] 历史记录不能查看完整参数、重新载入或重命名。
- [x] 对比页遗漏土层和秸秆情景参数。
- [ ] 对比页最多选 5 条但雷达图只画 2 条；当前已固定选择顺序并明确提示，仍待扩展多序列雷达图。
- [x] 多个图表缺少单位或图例；雷达图归一化区间属于展示假设但未说明。
- [x] 历史 JSON 导入没有明确版本校验和算法版本标记。
- [x] PDF 参数表遗漏秸秆情景参数。
- [x] 数字输入框可显示无法解析的文本，但计算仍悄悄使用上一个旧值。
- [x] 删除历史记录时先删数据库再删 PDF，文件占用失败会留下无法从应用管理的孤立文件。
- [x] 自定义 OpenAI 兼容接口必须填写 API Key，且粘贴完整 `/chat/completions` 地址会被重复拼接。

## 本轮执行范围

已修复所有 P0、P1，并完成大部分 P2。当前唯一明确保留项是“3–5 条记录的多序列雷达图”；表格仍完整展示最多 5 条记录，雷达图明确只取按选择顺序排列的前两条。

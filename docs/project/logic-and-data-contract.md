# SOC-Shield 业务口径与数据契约

## 目的

本文档固定当前应用的业务含义，避免后续维护再次把“字段名”“旧原型代码”或“图表文案”误当成科学公式。

当前算法版本：`kSocAlgorithmVersion = 2`。

## SOC 数据来源

SOC 不是由 pH、含水量、黏粉粒或全氮回归得到，而是按以下三维键直接查询原始数据表：

```text
施肥处理 × 侵蚀深度 × 土层键 -> SOC (g/kg)
```

- 施肥处理：`F`、`UNF`
- 侵蚀深度：`0/10/20/30/40/50/60/70 cm`
- 土层键：
  - `10` → `0-20 cm`
  - `25` → `20-30 cm`
  - `35` → `30-40 cm`
  - `45` → `40-50 cm`
  - `55` → `50-60 cm`

`F` 与 `UNF` 已是两套独立数据，禁止再叠加额外施肥系数。

未知键必须返回输入错误或抛出明确异常，禁止使用默认 SOC 值兜底。

## 碳库换算

单层碳库：

```text
carbonStorage = SOC(g/kg) × BD(g/cm³) × thickness(cm) / 100
```

单位为 `kg C/m²`。

碳密度：

```text
carbonDensity = carbonStorage / thickness(m)
```

单位为 `kg C/m³`。

当前应用只有一个统一容重输入，因此整个 0–60cm 剖面使用同一 BD。界面、PDF 和 AI 提示词必须明确这是一项简化假设。

## CK 静态比较

CK 定义为：**相同施肥处理、相同土层、侵蚀深度为 0cm 的记录**。

当前土层碳库差：

```text
currentLayerPool - sameLayerCkPool
```

当前土层 SOC 损失率：

```text
max(0, (sameLayerCkSoc - currentSoc) / sameLayerCkSoc × 100%)
```

禁止让深层记录与 0–20cm 表层 CK 比较。

## 0–60cm 剖面要求

剖面评估输入必须：

1. 从 0cm 开始并完整覆盖至 60cm；
2. 无重叠、无缺口；
3. 在 20cm 处有明确边界；
4. `layerId` 范围与 `thickness` 一致；
5. 当前剖面与 CK 剖面采用相同土层划分。

## 20年/100年字段

原始 DOCX 说明涉及“20年 0–60cm”和“100年 0–20cm”分析范围，但没有提供逐年末期值、时间序列或可复现的动态模型参数。

因此当前应用只计算：

- 0–60cm 当前剖面相对 CK 的静态碳库差；
- 0–20cm 当前表层相对 CK 的静态碳库差；
- 静态差值除以 20 的折算代理。

这些值不是已观测恢复趋势，也不是 20 年/100 年预测。历史 JSON 字段名
`netChange_20yr`、`netChange_100yr`、`recoveryRate_annual` 为兼容旧数据而保留，界面必须给出真实口径。

## 恢复力评估（第五章 5.1 口径）

恢复力评估页在常规计算之外提供三组派生指标，全部来自现有三维查表数据与统一容重换算，不引入新的模型假设：

1. **分层证据**：每个土层的单层碳库（式 5-1）、同层 CK 静态差与损失率；碳库差最小的土层标记为"薄弱层"。
2. **侵蚀亏缺矩阵**：8 个侵蚀等级的 0-60cm 剖面碳库差（式 5-2 累加）及 ÷20 的年化折算代理。
3. **情景覆盖对照**：秸秆三档碳输入（式 5-5）与年化亏缺代理的算术比较，结论分为三态：
   - `covering`：剖面无亏缺，或至少一档秸秆输入在量级上覆盖亏缺代理；
   - `partial`：最高档仅覆盖部分亏缺；
   - `deficit`：秸秆参数为零，无法评估。

覆盖对照仅比较管理碳输入与亏缺代理的量级关系，不构成 SOC 增量预测；结论文字与编号排查建议由该机制确定性生成，不经过任何模型。

## 辅助参数与管理情景

- pH、含水量、黏粉粒、全氮：辅助观测参数，不进入当前 SOC 查表或碳库换算。
- 秸秆生物量、秸秆碳比例、基础凋落物碳输入：仅进入 30%、50%、100% 秸秆还田情景。
- 秸秆情景不会反向修改实测 SOC。

秸秆碳输入：

```text
biomass(kg/ha) × carbonRatio × returnRatio / 10000
```

系统总碳输入：

```text
litterCarbonInput + strawCarbonInput
```

## 历史与版本

- 新计算记录写入算法版本。
- 旧数据库记录迁移后标记为算法 v1。
- 不同算法版本可追溯查看，但不应直接得出横向结论。
- 从旧记录“载入参数”只恢复输入；重新计算始终使用当前算法版本。

## PDF

- 每条历史记录最多维护一份应用本地 PDF：`soc-report-<recordId>.pdf`。
- 本地副本与历史记录关联；用户另存或分享不会替代该副本。
- 删除器只处理应用报告目录中的 PDF，禁止根据数据库中的任意路径删除外部文件。

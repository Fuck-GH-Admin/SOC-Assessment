# PDF 报告本地持久化设计

## 设计结论

应用生成的 PDF 应保留一份应用本地副本，并与对应的历史计算记录关联。用户在 Windows 上执行“另存为”或在 Android 上执行“分享”，都不会替代这份应用本地副本。

## 数据与文件链路

1. 每次成功计算先写入一条历史记录，并把数据库记录 ID 保存到当前计算状态。
2. 导出 PDF 时使用稳定文件名 `soc-report-<记录ID>.pdf`。
3. PDF 写入 `ApplicationDocumentsDirectory/SOC-Shield/report_pdfs/`。
4. 数据库 `history_records.pdf_path` 保存该文件的绝对路径。
5. 同一条计算记录再次导出时覆盖自己的应用本地 PDF，避免重复导出产生无法管理的孤立文件。
6. Windows 仍允许用户额外“另存副本”；Android 直接分享应用本地副本。

## 历史记录中的操作

存在 PDF 的历史记录会显示 PDF 标记，并支持：

- Windows：打开 PDF、打开所在文件夹、复制文件路径。
- Android：分享 PDF、复制文件路径。
- 其他桌面平台：打开 PDF、打开所在文件夹、复制文件路径。

如果用户从系统文件管理器手动删除了 PDF，历史页再次访问时会检测文件不存在，并自动清除失效的数据库关联。

删除历史记录时，应用会同时尝试删除关联的应用本地 PDF，避免留下孤立文件。用户手动“另存”的外部副本不受影响。

## 数据库迁移

- 数据库版本当前为 `3`。
- v2 新增可空字段：`history_records.pdf_path`。
- v3 新增字段：`history_records.algorithm_version`，旧记录默认标记为算法 v1。
- 旧数据库升级时只新增字段，不改写既有计算结果。

## 导入导出边界

历史 JSON 继续只保存可移植的计算数据，不导出本机绝对 PDF 路径，也不把 PDF 二进制内容塞进 JSON。导入到另一台设备的历史记录因此不会错误引用原设备文件。

## 存储边界

- 应用本地 PDF 会随应用数据长期保留。
- 卸载应用或清除应用数据会删除应用私有目录中的报告。
- 当前不设置自动过期或容量上限；报告由用户通过删除历史记录主动清理。
- 删除器只允许删除 `SOC-Shield/report_pdfs/` 下的 `.pdf`，即使数据库路径被破坏，也不会删除应用管理目录之外的文件。
